Diagnostics Reference¶

Every diagnostic PHPantom reports carries an identifier. It is shown with the message in your editor and under the message in analyze output, and it is what these take:

  • [[diagnostics.ignore]] identifier = "…" in .phpantom.toml (see Configuration),
  • an // @phpantom-ignore … comment (see Inline suppression),
  • analyze --code and --exclude-code (see CLI).

The severity is the default one. A few checks are off until you turn them on in [diagnostics]; their rows name the key. Framework checks run only in a project PHPantom detects as using that framework, and need no setting.

An identifier starts with the kind of problem (unknown_, invalid_, missing_, unused_, type_mismatch_, and so on). One that belongs to a framework or template language names it next, as in invalid_laravel_route or unclosed_blade_directive. A name a framework expects to be declared somewhere, but is not, is always invalid_.

Unused and unreachable code¶

These are shown dimmed rather than underlined, except unwritten_property.

Identifier Severity Reports
unused_import Hint A use import nothing in the file refers to.
unused_variable Hint A variable that is assigned or bound but never read.
unused_parameter Hint A trailing parameter the body never reads. Off unless unused-parameters is on.
unused_method Hint A private method nothing calls.
unused_property Hint A private property that is never read.
unused_constant Hint A private constant nothing reads.
unwritten_property Information A private property that is read but never written.
unreachable_code Hint Statements after a return, throw, exit, break, or similar.

External tools¶

Diagnostics from PHPStan, PHPCS, PHPMD, and Mago keep the tool's own identifier: PHPStan's error identifier (such as argument.type), the PHPCS sniff (such as Generic.Files.LineLength.TooLong), the PHPMD rule (such as UnusedLocalVariable), and the Mago issue code (such as invalid-return-statement). Both [[diagnostics.ignore]] and @phpantom-ignore match them the same way.
